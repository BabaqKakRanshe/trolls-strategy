# Ref_Buildings — 12 зданий по референсному листу

Набор построек в стиле `Strategy_Kit`, сделанный по листу концептов (синяя черепица,
тёплое дерево, холодный камень). Здания собраны процедурно в Blender 5.2 и экспортированы
в FBX под тот же контракт импорта, что и остальной кит.

`build_vitaria.py` не менялся — генератор здесь отдельный и переиспользует примитивы,
палитру и класс `Asset` из кита как библиотеку.

## Импорт в Unity

1. Скопируй `Buildings/*.fbx` в `Assets/Vitaria/Models/Buildings/` проекта.

   Путь важен: `VitariaModelPostprocessor` в `VitariaTools.cs` срабатывает только на
   `Assets/Vitaria/Models` и сам выставляет весь профиль импорта — нормали из файла,
   без тангенсов и анимации, lightmap UV, и главное — ремап материала на общий
   `Assets/Vitaria/Materials/Vitaria_Palette.mat`. Вне этого пути ничего не применится.

2. Больше ничего делать не нужно. Материал в FBX называется `Vitaria_Palette`, по этому
   имени постпроцессор и находит цель ремапа.

3. Палитру (`Textures/`) класть не надо, если в проекте уже есть `Assets/Vitaria/Textures` —
   копии приложены только для автономной проверки набора.

Не запускай `Tools > Vitaria > 1. Setup Material` ради этих файлов: он пересоздаёт
материал и откатывает `_EmissionColor`, `m_LightmapFlags` и `enableInstancing` к значениям
из кода. Постпроцессора достаточно.

## Контракт (проверено на всех 12 файлах)

- `UnitScaleFactor = 100.0`, `UpAxis=1 / FrontAxis=2 / CoordAxis=0` — как у кита;
  1 юнит Blender = 1 метр, пересчёта на импорте нет.
- Пивот внизу по центру, фундамент уходит под ноль на 4–15 см (у `Bld_House` кита — 15 см).
- Фасад смотрит в Unity +Z.
- Один меш, один материал `Vitaria_Palette`, UV попадают ровно в центры ячеек палитры
  (`(c+0.5)/16, 1-(r+0.5)/16`) — попадание в центр обязательно, иначе билинейная фильтрация
  подмешает соседний цвет.
- Плоские грани (`mesh_smooth_type="FACE"`), без тангенсов и вершинных цветов.

## Пересборка

```
blender --background --factory-startup --python Source/harness.py -- --all --out <куда> --render
```

`Source/harness.py` ждёт `build_vitaria.py` по пути
`F:/ClaudeGames/trollstrategy/assets/Strategy_Kit/Blender` (константа `KIT_BLENDER` в файле).
Одно здание — `--part bld_castle`. Каталог `Source/` нужен только для пересборки;
для игры достаточно `Buildings/`.

## Известные ограничения

- Здания не зарегистрированы в `KIT`/`asset_list.json` кита и не попадут в `Vitaria_Scene.fbx`.
  Полный ребилд кита их не тронет, но и не соберёт заново — это отдельный набор.
- Коллайдеров нет (`addColliders: 0`, как у всего кита). Их ставит
  `Tools > Vitaria > Create Prefabs`, который в проекте ещё ни разу не запускался.
- `Bld_Castle` (5068 треуг.) выходит за обычные для кита 1.5–4.5 тысячи: это четыре
  объёма в одном ассете. Около 350 треугольников — зубцы надвратной части, скрытые
  внутри жилого корпуса.
- `Bld_Barn` глубже цели на 23%: створки ворот распахнуты на 0.7 м перед фасадом и
  стоят на каменной площадке, её и добирает габарит.
- `common.window()` и `common.arrow_slit()` смещают вставку по жёсткому мировому −Y, не
  следуя за `rot`. На боковых стенах ставни и тёмный проём уезжают; часть зданий обходит
  это собственными вставками, `Bld_Cottage` — нет.
